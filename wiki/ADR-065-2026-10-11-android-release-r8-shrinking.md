# ADR-065: Android release R8 shrinking

## Situation

Google Play Console flagged the `development-store` app bundle for having no obfuscation and for
not being optimised. The Android project is generated by EAS at build time (no committed `android/`
folder), and Expo's default leaves R8 off (`android.enableMinifyInReleaseBuilds=false`). The bundle
therefore shipped every native class from React Native, the Expo modules, Firebase, Google Sign-In,
Play Services and AndroidX, unshrunk and unoptimised.

R8 only processes the native Java/Kotlin layer. The app's JavaScript is compiled to Hermes bytecode
by Metro and is untouched by it.

## Options considered

1. Leave R8 off and accept the Play warnings.
2. Commit a generated `android/` folder and edit `build.gradle` by hand.
3. Enable R8 through the `expo-build-properties` config plugin.

## Decision

Option 3. `app.json` sets `enableMinifyInReleaseBuilds` and `enableShrinkResourcesInReleaseBuilds`
to `true` for Android.

## Reason

- Smaller download and install, and faster cold start, from removing unused native code and resources.
- Keeps continuous native generation: no hand-maintained `android/` folder.
- The Android Gradle Plugin embeds the R8 mapping file in the app bundle, so Play deobfuscates crash
  stack traces without a separate upload.

## Consequences

- R8 can strip classes a library only reaches through reflection, which crashes at runtime. Each
  library normally ships its own keep rules, but every store build must be smoke-tested on a device
  (start-up, Google sign-in, video playback, secure-store) before promotion.
- If a library is missing keep rules, add them with `expo-build-properties`'
  `android.extraProguardRules` rather than turning R8 off.
- Release builds take slightly longer on EAS.
