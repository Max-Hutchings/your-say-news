# Infrastructure

Each child of `environments/` is an independent Terraform root. Reusable provider-specific modules
live in `modules/` and are referenced through repository-local paths. The reviewed application
commit therefore pins the environment and module implementation together.

The development root currently establishes the non-secret input/output contract only. It creates
no provider resources until the local modules, provider accounts and deletion-protection rules from
Phase 2 of the infrastructure plan are approved.

Remote state belongs in the HCP Terraform workspace `your-say-news-development`. Supply its
organisation/workspace details through an ignored `*.backend.hcl` file when running
`terraform init`; do not commit tokens or local state.

```shell
cd environments/development
cp development.backend.hcl.example development.backend.hcl
terraform init -backend-config=development.backend.hcl
terraform plan -var-file=development.tfvars
```

Commit the provider lock file generated by the approved Terraform version before CI planning is
enabled.
